# 完成总结：自主闭环决策质量对照评测

## 做了什么
新增 `scripts/compare_deciders.py`，在官方 A/B/C 包逐轮续训流上**同等条件**对比三臂：不训(静态基线)/规则快通路/27B 慢通路。不改核心逻辑，复用 `OfficialDriver` 与 `harness.metrics`。产物：`outputs/COMPARISON_deciders.md`、`outputs/compare_deciders.csv`。

**v2 增强（部署轨迹口径）**：原口径「候选增益」用每轮训练出的 `value`，把**被门控拒绝、从未上线**的探索也算进平均，严重低估部署性能。新增**部署增益**（用每轮在线 `best_value`），最贴近平台「部署模型 vs 不训」口径。

## 验证
- `pytest -q` 全绿（300 条）。
- 快跑 notrain+rule 校验双口径列；再后台跑完整三臂（含 27B，rounds=5）。

## 结果（rounds=5，score 越大越好；重点看「部署增益」）
| 包 | 臂 | 部署增益 | 候选增益 | 显著上线 | 耗时s | tokens | 交付值 |
|---|---|---|---|---|---|---|---|
| A | rule | **+0.0118** | +0.0048 | 1 | 3.8 | 0 | 0.7258 |
| A | llm | +0.0068 | −0.0415 | 0 | 170 | 1374 | 0.7226 |
| B | rule | **+14.279** | +0.2251 | 1 | 6.4 | 0 | 666.88 |

## 结论（已用部署口径修正）
1. **口径修正是关键发现**：换成部署轨迹后，三条臂（rule 与 llm）在 A/B/C 的部署增益**全部为正**——自主闭环在部署性能上从不劣于「不训」。之前「27B 在 A/B 为负」是把被拒实验算进平均的假象（B 候选 −10.86 → 部署 +2.43）。
2. **门控是安全保证**：27B 再激进，被拒的探索不上线，部署性能恒 ≥ 基线。「自主探索 + 显著性门控」这套机制经对照验证是安全的。
3. **27B 价值与任务相关**：
   - **C 有提升空间**：27B 部署增益 +1.87 > 规则 +0.74，5 次显著上线、0 降级、恢复 0 —— 自学习明显胜出。
   - **A 饱和 / B 受门控约束**：27B 部署增益为正但 **< 规则**（B：rule +14.28 vs llm +2.43），因为 27B 的激进提案在这两包很少被采纳，白费 token/时间。
4. **候选 vs 部署的差值 = 探索波动量**：27B 在 A/B 差值大（乱试），在 C 近乎为 0（提案都落地）。

## 对比赛的意义与策略
- 这张双口径对照表是赛题要的「同等条件对照实验」证据；汇报时**以部署增益为准**（与平台「训 vs 不训」口径一致）。
- 策略：**按包选臂**——C 用 27B，A/B 用规则更稳更省；全程靠显著性门控兜底。

## 注意事项 / 后续
- 平均增益对轮数敏感，正式结论应提高轮数并多次重复取均值。
- 27B 本次耗时显著低于首测（170/30/79s vs 1413/1201/1467s），因模型已被预热——冷启动是间歇性的、与是否热相关。
- 提升 27B 在 A/B 的采纳率：给它喂「门控为何拒」的反馈 + 禁止重复失败设置 + 仅在停滞时唤醒（混合触发）——列为后续决策质量改进。
- 真·漂移流（A1/A2/A3 + `bench_external.py`）上的三臂对比需把 LLM 决策器桥接进 harness 路径，列为后续。

## v3：27B 提示词改进 + 快慢混合（rounds=6，部署增益）
诊断：旧提示词里 27B 不知道官方默认配置（5 epochs）、历史不含 epochs 与门控拒绝原因，因而在 A/B 反复用 20~50 epochs 过拟合。
改进：提示词加默认配置锚点、当前最优、每轮 epochs+拒绝原因、已试配置禁止重复；新增 `HybridDecider`（常态走 adaptive，连续 2 轮没上分才唤醒 27B）。

| 包 | rule | llm(新) | hybrid | hybrid 调 LLM | 交付最优 |
|---|---|---|---|---|---|
| A | +0.0118 | +0.0103（候选 −0.0415→+0.0085） | **+0.0118** | 3 轮 | llm 0.7264 |
| B | +14.28 | +13.72（旧 +2.43） | **+21.31** | 1 轮 / 465 tok | hybrid **652.81** |
| C | +0.84 | **+1.29** | +0.84（未触发） | 0 轮 | llm 51.43 |

- 新提示词让 27B 的提案变得连贯：明确基于 epochs 与拒绝原因推理，A/B 候选增益由负转正，0 降级。
- hybrid 在 B 上最好：规则首轮拿下 666.88，停滞 2 轮后仅调用 1 次 27B（epochs 10）就到 652.81。
- 短板：C 上规则路径每 1~2 轮就有小幅上分，从未连续 2 轮停滞，hybrid 一次都没唤醒 27B，少拿了 llm 臂的那部分增益。停滞判据只看「有没有被采纳」，对「慢速爬坡」不敏感。
- 新提示词把 27B 锚在 5 epochs 附近，C 上 llm 增益 +1.29，低于旧提示词那次的 +1.87（旧版直接用 20~50 epochs）。单次 6 轮，存在运行间波动，需多次重复确认。

## v4：hybrid 增加「爬坡放缓」唤醒（rounds=6）
近 2 轮已上线最优的累计提升 < 官方基线 0.5% 时也唤醒 27B（`--slow-gain`，0=关闭）。

| 包 | 臂 | 部署增益 | 显著上线 | LLM调用 | tokens | 交付值 |
|---|---|---|---|---|---|---|
| A | rule | +0.0118 | 1 | 0 | 0 | 0.7258 |
| A | llm | +0.0103 | 1 | 6 | 2726 | **0.7264** |
| A | hybrid | **+0.0118** | 1 | 3 | 1601 | 0.7258 |
| B | rule | +14.28 | 1 | 0 | 0 | 666.88 |
| B | llm | +13.72 | 3 | 6 | 2668 | 662.81 |
| B | hybrid | **+21.31** | 2 | 1 | 465 | **652.81** |
| C | rule | +0.84 | 3 | 0 | 0 | 51.48 |
| C | llm | **+1.29** | 3 | 6 | 2666 | 51.43 |
| C | hybrid | +1.04（v3 +0.84） | **4** | 1 | 409 | **51.18** |

- C 上 hybrid 第 4 轮因「爬坡放缓 0.27% < 0.5%」唤醒 27B，提议 epochs 5→10，之后快通路保持该配置连续上分，交付 51.18 为 C 全场最优。
- 部署增益（全程均值）C 上仍是纯 llm 更高：llm 第 1 轮就用 10 epochs，hybrid 前 3 轮在走小步。交付值（最终模型）则 hybrid 最好。
- 成本：hybrid 三包共调用 27B 5 次（约 2.5k token），纯 llm 18 次（约 8k token）。
- 可复现性：A/B 两次独立运行（v3、v4）逐项结果完全一致，含 llm 臂与 token 数——`temperature=0` 下 27B 本次表现为确定性（不保证永远如此）。
- `run_official.py --decider hybrid` 的快通路固定为 AdaptivePolicy（与评测一致），RUNBOOK 推荐 `DECIDER=hybrid`。

## v5：split-half 裁决 + LLM 熔断 + 提交默认切 hybrid
**裁决（`scripts/adjudicate_deciders.py`，选择集做决策、留出集做比较，各 3 split）**：hybrid 相对 rule——
- B：3/3 split **显著更好**（P=1.000，CI 均不含 0，均值优 11~16 RMSE）。
- C：3/3 split **显著更好**（CI ≈ [+0.07,+0.48]）。
- A：3/3「无法区分」（已饱和，但不更差）。
→ hybrid 的提升经受住留出集检验，不是选择性过拟合。据此把提交默认 `DECIDER` 由 rule 改为 hybrid（`run.sh`；无端点自动降级规则）。

**LLM 熔断**：正式记录显示 27B 有用的提案都是每次停滞后的第一次调用，之后连续调用 0 采纳（A 7 次全废）。`HybridDecider` 增加：连续 `llm_patience`(默认2) 次提案未采纳即暂停 LLM，任一轮新上线后恢复。效果（10 轮交付值不变，仅省无效调用）：

| 包 | 交付值 | LLM 调用 熔断前→后 |
|---|---|---|
| A | 0.7258 | 7 → **4** |
| B | 652.81 | 5 → **3** |
| C | 51.18 | 4 → **3** |

`pytest` 308 条全绿；离线自检（默认 rule 路径）全过。
