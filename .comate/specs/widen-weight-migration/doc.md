# 函数保持式加宽 + 权重迁移（唯一剩下的性能杠杆）

> 超参搜索已证明到顶（多候选、网格、增强全无收益）。官方 `TRAINING_GUIDE.md` 明确允许
> "改变网络结构…需显式实现兼容的权重迁移，不能将一个新模型声明为原模型续训"。
> 本轮实现**函数保持式加宽（Net2Net）**：加宽隐藏层但迁移后输出与原模型**逐位一致**，再跑满 10 轮续训。

## 0. 已验证的可行性（探针结果）

函数保持迁移已实测正确——迁移后验证指标与原模型完全相同，证明是真续训而非重初始化：

| 包 | 原 hidden / params | 加宽后 | 迁移后验证指标 | 是否等于原始 |
|---|---|---|---|---|
| A | 32 / 4326 | 64 / 8646；128 / 17286 | Macro-F1 0.7140 | 是（0.7140） |
| B | 24 / 865 | 64 / 2305；128 / 4609 | RMSE 681.1598 | 是（681.1598） |

**单次续训**的初步结果（注意：不是公平对照，下面说明）：

| 包 | 原 10 轮基准 | 加宽 64 单次最好 | 加宽 128 单次最好 |
|---|---|---|---|
| A Macro-F1↑ | 0.7264 | 0.7271 | **0.7279** |
| B RMSE↓ | 666.88 | 677.31 | 673.07 |

A 上加宽只跑一次续训就略超原来的 10 轮结果；B 上更差——但 B 的 666.88 是**10 轮棘轮累积**的结果，
而探针只给了加宽模型**一次**续训。两者不可比。**本轮要做的就是把对照做公平：加宽后同样跑满 10 轮。**

## 1. 与比赛要求对齐

| 要求 | 落实 |
|---|---|
| "改结构需显式实现兼容权重迁移" | 实现 Net2Net 函数保持迁移，并用"迁移后指标与原模型逐位一致"自证是真迁移 |
| "不能把新模型声明为原模型续训" | 迁移保留原权重、Adam 一二阶矩、归一化、目标缩放、种子、steps/epochs；新单元 `w2` 行置 0，初始不改变任何输出 |
| 归一化只在初始训练集拟合 | 迁移不触碰 `mean/scale/target_mean/target_scale`，原样继承 |
| 参数量 < 100000 | 官方 `model.py` 自身上限；加宽后 A 17286 / B 4609 / C 待测，均远低于上限 |
| 可审计、可复现 | 迁移脚本确定性（固定种子、新权重 σ=1e-3）；记录迁移前后指标与 sha256 |
| 合规声明 | 提交材料中显式说明"加宽 + 函数保持迁移"的实现与自证方式 |

**风险（如实记录）**：加宽会改变 `parameter_count`（官方给的基线参数量是 4326/865/833）。官方文档允许改结构，
`model.py` 也只校验 `1≤hidden≤128` 与参数量上限，官方 `predict.py` 从 checkpoint 元信息读 hidden，能正常加载。
但"是否接受加宽后的模型参与评分"最终以官方口径为准 → **保留未加宽结果作为随时可回退的方案**，两套都留。

## 2. 设计

```
新增 src/driver/migrate.py      函数保持式加宽：load → 扩 w1/b1/w2（w2 新行=0）→ 扩 Adam 矩（新槽=0）
                                → 更新 meta.hidden/parameter_count → save；并校验"迁移后指标 == 原指标"
新增 scripts/widen_and_run.py   迁移 + 生成自定义 profile JSON（仅改 hidden）+ 跑满 10 轮驱动 + 对照原始
修改 src/driver/package.py      允许覆盖 profile config 路径与起始 checkpoint
修改 src/driver/trainer.py      支持传入自定义 profile JSON 路径（官方 train.py 已支持 --profile *.json）
修改 src/driver/loop.py         支持指定初始 checkpoint（替代随包 checkpoint）与自定义 profile
```

要点：
- 迁移产物写到 `outputs/widen/<profile>/hidden-<H>/checkpoint.npz`，不污染 `base/`。
- 自定义 profile JSON 只改 `hidden`，其余（profile/task/classes/seed/lr/batch/epochs）与官方一致，
  否则官方 `train.py` 会以"seed/hidden/profile 不匹配"拒绝。
- 门控基线仍用**官方随包基线值**（A 0.7140 / B 681.16 / C 52.87），保证"不低于官方基线"的判定口径不变。

## 3. 实验（公平对照）

对 A/B/C 各跑三组，10 轮、固定种子、同一门控：

| 组 | 起点 | hidden |
|---|---|---|
| 原始（已有） | 随包 checkpoint | 官方值 |
| 加宽 64 | 迁移后 checkpoint | 64 |
| 加宽 128 | 迁移后 checkpoint | 128 |

记录：最优验证指标、上线/训练次数、耗时、参数量。判定标准：加宽组最优指标**显著优于**原始组才采纳
（A 提升需 > 0.004 的验证噪声幅度；B/C 以 RMSE 相对改善 > 1% 为界），否则如实记为无效。

## 4. 验证

1. 迁移自证：每次迁移后断言"验证指标与原模型一致"，不一致即报错退出。
2. 官方 `train.py` 能以自定义 profile + 迁移 checkpoint 正常 `--resume`（已在探针验证）。
3. `python3 -m pytest` 全绿；未加宽的默认路径（`run_official.py`）行为完全不变。
4. 固定种子复跑一致。

## 5. 边界

| 情况 | 处理 |
|---|---|
| 加宽后参数量超官方上限 | `model.py` 自身会拒绝；我们在迁移前先算并提示 |
| 官方拒绝非原始结构 | 保留未加宽结果，可一键回退（两套 checkpoint 都在 outputs/ 留存） |
| 加宽后反而更差 | 如实记录，不采纳；这也是有价值的容量-数据匹配结论 |
| B 需 label-provenance | 复用现有自动生成逻辑 |
