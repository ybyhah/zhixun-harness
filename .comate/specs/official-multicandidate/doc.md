# 官方续训多候选搜索（提性能分）

> 目标：在 10 轮续训预算内，每轮尝试**少量候选超参**（epochs/lr），用官方验证指标择优，
> 比"单点固定猜测"更稳地逼近更优续训轨迹。直接对准客观分"平均性能提升 15 分"。

## 0. 动机（已实测的头寸）

同一包 A、同样 10 轮，仅改每轮 epochs：best Macro-F1 = **5→0.7264 / 3→0.7253 / 15→0.7199**。
说明：续训超参对结果敏感、且"更多 epoch 反而过拟合"。固定一个 epochs 要么保守要么过头；
**每轮并行试几个候选、按验证择优**能稳定抓到更优点，这正是赛题鼓励的"做对比实验、有依据地更新"。

## 1. 与比赛要求对齐

| 要求 | 落实 |
|---|---|
| 客观分性能 30 : 资源 5，性能优先 | 多候选每轮多训 K 次，换更优模型；资源代价记录，权重小、值得 |
| 受控 RSI、轮数上限 | 轮数仍 10；每轮候选数 K 有上限（默认 3），不无限搜 |
| 有依据地更新、门控 | 候选都在官方验证集打分，门控择优并保证不低于基线 |
| 可审计 | 审计记录每轮所有候选及其验证分、选中项 |
| 不改官方 baselines | 只多次调用官方 `train.py`，不动其逻辑 |

## 2. 设计（扩展 `src/driver`，默认行为不变）

- `policy.py` 增加 `expand_candidates(base_plan, k, round_index) -> list[RoundPlan]`：
  以 base_plan 为中心，小幅扰动生成候选——lr ∈ {base, base×0.5, base×2}、epochs ∈ {base}（必要时 {base, base-2}），
  全部裁剪到官方合法区间，去重，最多 k 个。规则/LLM 决策给出的 base_plan 作为中心。
- `loop.py` 增加 `candidates`（默认 1，保持现状）。当 k>1：
  1. 本轮从**当前被采纳 checkpoint** 出发，对每个候选各训一次（官方 train.py），输出 `round-k/cand-j`；
  2. 取验证最优候选；
  3. 该最优候选过门控（不低于基线、较当前最优有提升）才上线，否则不上线；
  4. 审计记录全部候选分与选中项，`trainings` 计入所有候选训练次数。
- `run_official.py` 加 `--candidates K`（默认 1）。K=1 时与现状完全一致。

## 3. 防过拟合与诚实

- K 小（默认 3），避免对验证集过度搜索；验证只是代理，平台最终在隐藏测试打分。
- 报告中如实给出：验证提升 vs 多训的次数（资源代价）；若某包多候选相比单候选无额外提升，照实写。
- 固定种子；候选顺序确定，结果可复现。

## 4. 影响文件

| 文件 | 改动 |
|---|---|
| `src/driver/policy.py` | 加 `expand_candidates`（纯函数，可单测） |
| `src/driver/loop.py` | 支持每轮多候选训练+择优+门控+审计（默认 1 不变） |
| `scripts/run_official.py` | 加 `--candidates` |
| `tests/test_driver.py` | 补候选扩展（去重/裁剪/上限）与多候选择优（mock 子进程）测试 |
| `outputs/CONCLUSIONS.md` | 补单候选 vs 多候选 A/B/C 对照 |

## 5. 验证

1. A/B/C 各跑 `--candidates 3`，对比 `--candidates 1` 的 best 指标、上线次数、训练次数、耗时。
2. 目标：best 指标不劣于单候选，力争更优；门控仍保证 ≥ 官方基线。
3. 固定种子复跑一致；`python3 -m pytest` 全绿；K=1 默认行为与改动前一致。

## 6. 边界

| 情况 | 处理 |
|---|---|
| 候选去重后不足 k | 用实际数量，不报错 |
| 某候选训练失败/超时 | 跳过该候选，其余照常；全失败则本轮不上线 |
| 多候选都不如当前最优 | 不上线，下一轮从当前最优继续 |
| 资源/耗时上升 | 如实记录，K 可调；C 包单候选 ~8s/轮，K=3 约 24s/轮，10 轮可接受 |

## 7. 不在本轮

- LLM 直接生成候选集（本轮候选由规则扰动；LLM 仍只给 base_plan 中心，后续可让 LLM 一次提多候选）。
- 改 `baselines/` 代码层面的结构/特征优化。
