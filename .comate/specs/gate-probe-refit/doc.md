# 门控 probe + 全窗口重训（holdout_refit）

> 承接 `gate-temporal-validation` 的负结果：时序验证让门控更诚实，却因"排除最新批次训练"损失适应性，端到端反而下降。
> 本轮目标：**既拿诚实门控，又不丢最新批次的适应**——门控用 probe 诚实打分，通过后在全窗口重训再上线。

## 0. 与比赛要求的对齐（不跑偏）

| 赛题要求 | 本轮如何契合 |
|---|---|
| `[规则]` 模型层自迭代（受控 RSI 第一层） | 这正是"怎么更新模型"的策略改进，属闭环第三/四步，核心赛点 |
| 客观分性能 30 : 资源 5，性能优先 | 为涨性能每次上线多一次重训；上线次数少（3~5），资源代价可控，方向正确 |
| C3 4 核 8G 无 GPU | 工业模型仍是 HistGBDT 量级；多的训练已被 `max_total_trainings`、`train_timeout_s` 护栏约束 |
| "不是每批都训" | 不改触发逻辑，只改"决定上线后怎么产出要上线的模型"，NOOP 比例不变 |
| C9 至少 3 次完整闭环 | 审计记录字段不变，闭环计数不受影响 |
| 可复现、可审计 | 固定种子；审计记录会同时留存 probe 门控分与重训信息 |

不新增任何大模型/外网依赖，不碰提交镜像边界。纯第一层模型自迭代的工程改进，不偏题。

## 1. 机制

当前（`in_batch`）：候选在"含最新批次"的窗口上训练，门控在同批 30% 切片上打分 → 门控分虚高（+0.38/+0.52）。
上一轮（`holdout_recent`）：候选训练排除最新批次，门控在整个最新批上打分 → 门控诚实，但部署的模型没学到最新批次 → 性能跌。

本轮（`holdout_refit`）把两步拆开：

```
1. probe 训练：在"截至上一批"的窗口上训候选（每个动作一个 probe）
2. 诚实门控：probe 在"整个最新批次"（它没见过）上打分，过三道门控
3. 选优：多候选里取门控分最高且通过者
4. 全窗口重训：对选中的动作，用"含最新批次"的全窗口重训一个部署模型
5. 上线部署模型（而非 probe）
```

门控判定基于 probe（诚实、不乐观）；上线的是重训模型（学到了最新批次，适应性不丢）。

## 2. 为什么这样不会偷看未来

- probe 的验证集是**已经到手并提交过**的最新批次，不是未来数据，串行卡点不变。
- 重训用的也只是"截至当前批"的全部历史，与现状训练数据范围一致。
- 唯一变化：把"用于决策的模型"和"用于部署的模型"分开——决策模型少看一批（为诚实），部署模型看全（为适应）。

## 3. 影响文件

| 文件 | 改动 |
|---|---|
| `src/harness/decide/actions.py` | `split_last` 的 `val_mode` 增加 `holdout_refit`：切分行为同 `holdout_recent`（probe 池 = `X[:-1]`，验证集 = 整个 `X[-1]`） |
| `src/harness/loop.py` | `_after_submit`：`val_mode=="holdout_refit"` 且批次数≥2 时，向 `_compete` 传入 `refit_pool=self.pool`（全窗口）。`_compete`：某候选通过并选中后，用 `refit_pool` 对该动作重训出部署模型，成功则 stage 重训模型、失败回退 probe |
| `configs/*.yaml` | 不改默认（仍 `in_batch`）；`holdout_refit` 仅通过 variant 或 `--set` 启用 |
| `scripts/run_loop.py` | `VARIANTS` 增加 `holdout-refit`（`gate.val_mode=holdout_refit`） |
| `tests/test_decide.py` / `test_loop.py` | 补：holdout_refit 切分等价 holdout_recent；重训模型训练数据覆盖最新批次；重训失败回退 probe |

主闭环其余逻辑、审计、指标口径不变。

## 4. 实现要点

- `_compete` 新增可选参数 `refit_pool`。仅在 promote 分支（有候选通过）触发重训，全部被拒/无候选分支不变。
- 重训复用现有 `_try_action(idx, decision, refit_pool)`，不新增训练代码路径；受同一超时与预算护栏约束，重训也计入 `used` 训练次数。
- 重训模型训练失败（如单类）时回退用 probe `cand` 上线，保证不因重训把本可上线的更新弄没。
- `replay_pairs`（抗遗忘指标）本轮仍用 probe 的门控回放分作代理，记为已知简化；若 A/B 显示抗遗忘明显变化，再决定是否对重训模型重算回放分。

## 5. 验证方法

1. **端到端 A/B**：A1/A2/A3 对比 `full`（in_batch）、`holdout-gate`（holdout_recent）、`holdout-refit` 三者的综合性能、最差阶段、恢复、上线/训练次数、耗时。
2. **门控诚实性**：holdout_refit 的门控分仍来自 probe，保持 `holdout_recent` 的低乐观度。
3. 固定种子各跑两次确认可复现；默认 `in_batch` 的 A1/A3 逐批结果与改动前完全一致。
4. `python3 -m pytest` 全绿。

## 6. 预期与去留（不预设，按数据）

- 期望：综合性能 ≥ `in_batch`（因为部署模型适应性不丢），同时门控更诚实（利于"稳定性/恢复"相关项）。
- 若综合性能确实 ≥ in_batch：采纳 `holdout_refit` 为推荐默认，更新结论。
- 若仍不及 in_batch：如实记录，保留 in_batch，分析原因（如重训引入的方差、probe 门控过严拦掉了有益更新）。
- 资源：报告里给出多出的训练次数与耗时，对照赛题资源效率项，确认代价可接受。

## 7. 边界

| 情况 | 处理 |
|---|---|
| 批次数 < 2 | 不启用 refit，退回 in_batch 切分 |
| 重训动作单类/失败 | 回退 probe 候选上线 |
| 重训超时 | 按现有护栏丢弃，回退 probe 候选 |
| 多候选都通过 | 先按 probe 门控分选最优动作，再只对该动作重训一次（不是每个候选都重训） |
