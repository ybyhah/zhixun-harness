# 自适应探索策略（打资源效率分 + 救回被浪费的轮次）

> 性能三条路（超参/容量/损失）已证明到顶。但客观分不只看"最终最优"，还有**资源效率 5 分**
> （单位增益消耗的算力）。现有规则策略有明确浪费，这是还能拿分的地方。

## 0. 问题：现有策略会把学习率衰减到无效区

规则策略在每次"不上线"后把学习率减半。审计实测：

| 包 | 10 轮里不同的验证值 | 与上一轮零变化的轮次 | 末轮 lr |
|---|---|---|---|
| A | 只有 5 个 | **4 次** | 2.34e-05 |
| B | 10 个 | 0 | 1.17e-05 |
| C | 10 个 | 0 | 1.25e-04 |

A 最典型：轮 4、5、6 的 lr 分别是 7.5e-4 / 3.75e-4 / 1.875e-4，验证分**一模一样 0.7183**；
轮 8、9、10 又都是 0.7183。lr 衰减到这个量级，5 个 epoch 已经动不了模型——
**这 4 轮训练是纯消耗、零信息**，既浪费资源分，也占掉了本可以探索别处的轮次。

## 1. 目标

- **主目标**：去掉零信息轮次，提高"单位增益的训练次数/耗时"（资源效率 5 分）。
- **次目标**：腾出的轮次换方向探索，有机会（不保证）超过当前 0.7264 / 666.88 / 51.38。
- 不降低已有最优指标；默认策略仍可一键回退。

## 2. 设计：停滞检测 + 多轴探索 + 无效轮跳过

替换 `RulePolicy` 的单轴（只减 lr）逻辑，改为 `AdaptivePolicy`：

```
状态：已试过的 (parent, epochs, lr) 集合、最近若干轮的验证值
决策：
  1. 停滞检测——若上一轮验证值与前一轮差 < tol（默认 1e-9），判定"lr 已进入无效区"
  2. 换轴——此时不再减 lr，而是沿另一个轴探索：epochs ×2（上限 50），lr 回弹到上次有效值
  3. 去重——若 (parent, epochs, lr) 已试过，直接判 NOOP 跳过本轮训练（不浪费）
  4. 常规——有进展就保持；被拒但仍有变化则按原来减半 lr
  5. 兜底——若所有轴都已耗尽（无新配置可试），本轮 NOOP
```

`NOOP` 是官方认可的一等决策（"不更新也可以是正确的系统决策"），跳过的轮次仍写审计
（含"为何跳过"），只是不消耗训练算力。

## 3. 影响文件

| 文件 | 改动 |
|---|---|
| `src/driver/policy.py` | 新增 `AdaptivePolicy`（实现同一 `Decider` 协议）；`RoundPlan` 增加 `skip: bool` 与 `reason` |
| `src/driver/loop.py` | `plan.skip` 为真时不训练、不计 `trainings`，照常写审计（动作记为 NOOP） |
| `scripts/run_official.py` | `--policy {rule,adaptive}`，默认 `rule`（保持现状可回退） |
| `tests/test_policy.py` | 新增：停滞检测触发换轴、重复配置判 NOOP、有进展时保持、轴耗尽后 NOOP、永不返回非法超参 |
| `outputs/CONCLUSIONS.md` | 补资源效率对照 |

## 4. 验证与判定

A/B/C 各跑 `--policy rule` 与 `--policy adaptive`，固定种子，对比：

| 指标 | 期望 |
|---|---|
| 最优验证指标 | **不低于**现状（A 0.7264 / B 666.88 / C 51.38） |
| 实际训练次数 | 明显少于 10（A 预期省掉 4 次左右） |
| 单位增益训练次数 / 耗时 | 改善（这是资源效率分的口径） |
| 审计完整闭环数 | 仍 ≥ 3（NOOP 轮也记录四要素） |

**判定**：指标不退且训练次数下降 → 采纳为推荐默认；若指标退了 → 不采纳，如实记录。

## 5. 边界

| 情况 | 处理 |
|---|---|
| 首轮无历史 | 按基础超参训练，不跳过 |
| 全部轮次都被判 NOOP | 至少保证第 1 轮训练过，避免一次都不训 |
| epochs 换轴触顶（50） | 回到 lr 轴小幅上调；都耗尽则 NOOP |
| 停滞判据过敏 | tol 可配置；用"与上一轮差值"而非"与最优差值"，避免把正常小步进误判为停滞 |
| LLM 慢通路 | `AdaptivePolicy` 同样可作为 `LLMDecider` 的 fallback（协议一致） |

## 6. 诚实边界

资源效率只占 5 分，这项优化的上限有限。**真正的大头仍是专家分 65**
（方法设计 30、实验分析 15、安全与工业落地 10、报告与答辩 10）与提交硬门槛
（Docker C5/C11、技术报告、演示视频、来源声明）。本轮做完就应转向那边。
