# C 包平台反馈搜索设计

## 目标与可观测边界

C 包的最终目标是降低平台隐藏测试集 RMSE。SDK 不会在运行中返回隐藏标签或隐藏集指标；
`submit_candidate()` 返回的 `summary.metrics` 明确是平台公开验证摘要。因此系统分为两层：

- 单次平台运行内，公开验证摘要是候选、父模型和历史产物之间比较的唯一授权依据；
- 两次提交之间，以平台试运行报告中的隐藏集汇总成绩检验策略是否真正泛化。

本地公开验证集和本地 C-MAPSS test 仅用于确认训练及预测链路正常，不参与正式产物选择，
也不用于硬编码搜索参数。Harness 不伪称能够在单次运行中读取或学习隐藏测试标签。

## 已确认的问题

当前 C 包一次训练多个 epoch，再按本地公开验证指标选择其中一个 epoch。公开验证集包含每台
发动机的全部循环，而平台隐藏测试按截断序列的最后观测点评分；两者存在分布与协议偏差。
因此，本地验证改善不能可靠推出平台隐藏 RMSE 改善。

此外，现有资源策略会在连续两轮无改善后跳过一次训练。C 包最多只有 10 轮平台反馈，跳过
训练会浪费一次可用于搜索隐藏集更优候选的机会。

## 方案

### 单步候选

C 包每轮固定续训 1 个 epoch。这样每个候选只对应一次明确的参数更新，平台反馈可以归因于
本轮学习率，而不会被本地 best-epoch 选择混淆。A、B 包保持现状。

候选始终从 SDK 提供的当前父产物续训。平台采纳候选后，下一轮从新产物继续；平台拒绝候选
后，下一轮仍从原父产物尝试不同学习率。

### 平台反馈控制

Qwen 提示包含 C 包截至当前轮的全部平台公开验证历史，每条只保留：

- 平台公开验证 RMSE 与 NASA 指标；
- 学习率；
- 候选是否被采纳；
- 父产物和最终选中产物；
- 平台漂移判定。

Qwen 只负责提出下一轮学习率和简短假设。`epochs` 对 C 固定为 1，不交给模型自由扩大。
模型输出解析失败时使用确定性回退，不中断轮次。

同一父产物下不得重复已经测过的学习率。若 Qwen 给出重复值，按现有学习率依次尝试
`0.5x`、`2x`、`0.25x`、`4x`，并限制在现有合法范围内，选择第一个未尝试值。
这只是搜索保护，不使用本地测试成绩。

### 上线与恢复

主指标仍从任务合同读取，C 当前为 RMSE、越低越好。候选只有在平台公开验证 RMSE 优于
当前父产物时才可采纳。平台同时返回 NASA 分时，保留现有 5% 显著恶化否决规则；NASA
不替代 RMSE 成为主指标。

每轮还比较平台允许恢复的历史产物。最终选择当前候选、当前父产物和可恢复历史产物中平台
公开验证 RMSE 最低且通过 NASA 否决规则的产物。缺少或非有限的平台主指标时保守保留
父产物，绝不用本地指标补位。

### 轮次利用

C 包不适用“连续两轮无改善后跳过训练”的资源策略，最多 10 轮均用于产生新候选。
A、B 包的资源策略保持不变。训练失败时仍按现有逻辑保留父产物并正常结束该轮。

## 数据流

1. SDK 提供当前父产物、历史记录和平台允许访问的历史产物。
2. Harness 提取全部 C 平台历史并生成压缩提示。
3. Qwen 提议学习率；Harness 校验范围并消除重复值。
4. 从父 checkpoint 续训 1 个 epoch，提交候选。
5. 读取平台 `summary.metrics`。
6. 仅按平台 RMSE 和 NASA 安全否决比较候选、父模型及历史最佳产物。
7. 记录本轮配置、平台指标、选择理由和模型调用 ID，供下一轮使用。

平台运行结束后读取试运行报告，使用隐藏集汇总指标做跨提交验收。第一次报告的 C 基准为：

- 隐藏测试 RMSE：`56.455008`；
- 隐藏测试 NASA 非对称分：`96,699,827,373.39221`。

下一版只有在隐藏测试 RMSE 低于 `56.455008` 时才能认定本次 C 优化有效；NASA 分作为
工业安全辅助指标，应同时下降，至少不得出现数量级恶化。该验收发生在平台运行完成后，
不会把隐藏标签或样本带入训练容器。

## 改动范围

- `submission/contest_submission.py`
  - C 固定单 epoch；
  - C 不跳过训练；
  - C 使用全部压缩平台历史；
  - 同一父产物下按学习率去重并确定性换轴。
- 现有 submission 策略测试
  - 覆盖 C 单步、禁用跳过、完整历史和学习率去重；
  - 保留平台摘要唯一决策、NASA 否决及历史恢复测试。
- 运行说明
  - 说明 C 的平台反馈搜索方式及本地指标不参与正式选型。

不修改官方 SDK、不修改官方数据包、不引入新依赖，也不改变 A、B 的既有训练策略。

## 验证标准

1. C 无论 Qwen 返回多少 epochs，实际训练命令始终为 `--epochs 1`。
2. 连续拒绝不会让 C 进入 `training_skipped`。
3. C 第 4 轮以后提示仍包含早期平台历史，但保持在模型输出预算内。
4. 同一父产物下不提交重复学习率；重复建议会确定性换轴。
5. 候选的本地指标更好、平台公开验证 RMSE 更差时仍保留父产物。
6. 历史产物只有在 SDK 本轮允许访问且平台公开验证 RMSE 最优时才恢复。
7. 正式 SDK 测试、submission 策略测试和 Docker `describe` 验收通过。
8. 下一次平台试运行报告的隐藏测试 RMSE 低于 `56.455008`，否则只算工程修复完成，
   不宣称 C 性能问题已解决。

## 明确不做

- 不根据本地官方 test 成绩调整学习率表或上线阈值；
- 不增加新的模型结构、损失函数或第三方优化库；
- 不让 Qwen 直接绕过平台门控选择产物；
- 不宣称 SDK 公开验证摘要是隐藏测试反馈；
- 不改动 A、B 包策略。
