# 客观评分下一阶段优化设计

## 目标

在正式 SDK 路径保持平台指标唯一跨产物决策依据的前提下，依次改善平均性能、最差阶段与恢复、稳定性和资源效率，并把三个官方包现有 `training.json` 中的静态基线纳入自动汇总。

## 证据约束

- 静态基线直接读取 `base/cpu-*/training.json`：A 使用 Macro-F1，B/C 使用 RMSE。
- 已有 C 损失实验表明高估权重 1.5、2.0、3.0 均劣于官方权重 1.0；正式路径恢复官方损失，不继续固化无效权重。
- A 的 10 epoch 与 20 epoch 本地对照得到同一最佳 epoch 和同一 Macro-F1，20 epoch 只增加耗时；保留 10 epoch 强起点。
- 跨轮上线、历史恢复和漂移判断仍只使用平台 `summary.metrics`；本地验证仅选择单次训练内部的 epoch。

## 修改设计

### C 多目标与早停

C 的 epoch 比较同时使用 RMSE 和 NASA 非对称分。RMSE 改善时允许 NASA 最多相对增加 5%；NASA 至少改善 5% 时允许 RMSE 最多相对增加 1%。连续 3 个 epoch 没有多目标改善就停止 C 本轮训练。平台 C 门控使用同一 5% NASA 容忍，避免零容忍阻断小幅权衡，但禁止明显 NASA 退化。

### A 稳定门控

A 前两轮继续使用 10 epoch、0.01 学习率。后续平台候选只有在 Macro-F1 绝对提升至少 0.002，且 Accuracy 不比父模型低超过 0.002 时才上线。第一轮没有父指标时仍接受有效候选。

### B 停滞换轴

B 一轮无改善后继续使用现有确定性换轴。换轴轮仅清零 Adam 一阶和二阶动量，不改变累计训练步数、权重、归一化或随机种子；训练报告记录该动作。

### 资源效率

Qwen 只读取最近 3 轮压缩历史，关闭 thinking，输出上限 96 Token。至少完成 3 个正式闭环后，如果同一父模型连续两轮无改善且最近漂移均非 HARMFUL，可跳过一轮工业训练；跳过不会连续发生，下一轮恢复实验，避免永久错过后续改善。

### 客观评分代理表

新增标准库脚本，读取三个静态基线和 `outputs/official_*_rounds.csv`，输出平均相对提升、最差轮次相对基线、恢复到基线轮数、最大回撤、总耗时、上线率和无效训练数。该表是提交前比较工具，不冒充平台正式分数。

## 验收标准

1. 新增行为均有先失败后通过的单测。
2. 三个静态基线由当前官方包自动读取且数值正确。
3. 正式 SDK 契约测试、本地 SDK 测试和提交镜像 `describe` 通过。
4. 代理表能从当前三份官方 CSV 生成，并明确标注为 proxy。
5. 平台专属验证项保留为下一次试运行检查：真实 call ID、无 `pred_failed`、平台历史非空和新客观指标。
