# 平台摘要驱动的 Harness 修复设计

## 目标

让正式 `submission` 完整遵守 `contest-harness-sdk 1.0.2`：候选提交后以平台返回的公开验证摘要为唯一上线计量依据，下一轮 Qwen 能读取真实平台历史，同时修复提交镜像和运行文档不一致的问题。

## 范围

本次只修改正式提交链路及其测试和运行说明：

- `submission/contest_submission.py`
- `submission/Dockerfile`
- `scripts/local_sdk_test.py`
- 新增正式提交逻辑的单元测试
- `RUNBOOK.md`
- 根目录 `Dockerfile` 的用途说明

不重构旧的 `src/driver` 本地实验系统，不修改赛事 SDK，不改动官方 A/B/C checkpoint 或公开数据。

## 平台指标选型

1. 候选训练完成后仍调用 `rnd.submit_candidate()`。
2. 从返回值的 `summary.metrics` 读取候选的权威平台指标。
3. 父模型指标按以下顺序获取：
   - 当前父产物回执中可用的平台摘要；
   - 最近一条历史记录中与当前父产物对应的平台摘要；
   - 任务合同中明确提供的平台父模型或基线指标。
4. 如果首轮没有任何父模型平台指标，但候选平台主指标合法，则采用候选。
5. 从第二轮开始，候选只在平台主指标严格优于父模型时采用；指标缺失、非有限或结构不合法时保守保留父模型。
6. `training.json` 的本地指标只作为诊断信息写入配置，不参与上线选择，也不冒充平台分数。
7. `reason` 明确记录候选平台指标、父模型平台指标、指标方向及最终选择。

## 历史与 Qwen

历史解析支持平台实际可能出现的嵌套结构，包括 `summary.metrics`、`metrics` 和历史 `configuration.platform_metrics`。Qwen 提示包含最近六轮的：

- 平台主指标；
- 训练轮数和学习率；
- 是否选中候选；
- 已尝试配置。

模型调用继续发生在训练前，用于提出 `epochs`、`learning_rate` 和实验假设。模型输出使用 JSON 响应格式并限制长度，减少无效文本和解析失败。

## 重复实验与客观评分

从历史配置构造已尝试的 `(父产物, epochs, learning_rate)` 集合。若 Qwen 给出重复配置，使用最小的确定性候选序列换轴，避免从同一父模型重复执行完全相同实验。

本轮决策记录平台指标和资源信息，为后续按以下四项生成证据：

- 平均性能提升；
- 最差阶段与恢复速度；
- 稳定性；
- 资源效率。

C 包的选择仍以任务合同声明的主指标为协议依据；NASA 非对称分、MAE 等平台附加指标作为稳定性否决项：如果候选主指标改善但已提供的 NASA 分显著恶化，则保留父模型。没有平台父指标时不使用本地 NASA 分代替。

## 镜像和文档

- `submission/Dockerfile` 必须复制 `submission/decision.py`。
- 正式构建命令统一使用 `-f submission/Dockerfile`。
- 根目录 `Dockerfile` 明确标记为旧版本地实验镜像，不得用于平台提交。
- RunBook 把正式平台 SDK 镜像放在首位，旧本地流程单独标记。

## 错误处理

- 模型回复解析失败：保留真实 `call_id`，回退安全超参。
- 平台候选摘要缺失或主指标非法：保留父模型并在 `reason` 说明。
- 训练失败：保留父模型，仍引用本轮真实模型调用。
- `decision.py` 导入失败不再静默发生：镜像构建测试检查文件存在。

## 验收标准

1. 测试证明平台摘要而非本地验证值决定上线。
2. 测试证明首轮无父平台指标时采用合法候选。
3. 测试证明后续候选不优于父平台指标时保留父模型。
4. 测试证明平台摘要缺失时保守保留父模型。
5. 测试证明 Qwen 提示包含平台历史指标和已尝试配置。
6. 测试证明重复配置会换轴。
7. 本地 SDK 合约测试通过。
8. 正式镜像包含 `decision.py`，`describe` 输出协议 v2。
9. Docker 构建和本地宿主模拟通过；真实 Qwen `call_id` 由下一次平台提交报告确认。
